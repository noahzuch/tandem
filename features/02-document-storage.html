F02 · Document storage & round trip specification pending

HTML stays the file on disk; the live Y.Doc is written back without losing anything.

Overview

While a document is open the live truth is a Yjs document in the server; the server renders HTML from it, pretty-prints it, restores island source byte-for-byte, splices it into the original <head> and writes spec.html plus .ystate. When closed, the HTML file is all there is. Includes the fidelity guarantees, the collab check linter, startup (load .ystate if the hash matches, else parse HTML headlessly), restart behaviour and the file-watcher safety net that 3-way-merges direct edits to spec.html.

What the spikes settled

  • HTML is the storage format and the agent's language — not ProseMirror JSON or Yjs (03).
  • Plain Tiptap drops diagrams, layout, ids and classes on first load (02); with islands and attribute preservation: 0 dropped / 0 altered on all three samples (04).
  • <head> split off and kept byte-identical; prettier on save turns a one-word edit into a 127-char diff (02).
  • Store debounced (0.8 s after last change, at most every 3.2 s), skipped if HTML is unchanged (arch).
  • collab check flags HTML that edits badly, each rule with a fix (03).

Open / to decide

  • Reduce <p> injected into block containers via an “implicit paragraph” (N23).
  • Audit every extension for attributes it writes into the HTML; vendor small ones (N8).
  • Block ids (data-bid) visible in the saved HTML — decision pending (decisions).
  • Offline edits in a tab are lost if spec.html changed while the server was down (arch).
