Spec: Offline sync for field notes

Status: Draft · Owner: Noah · Last updated: 2026-10-24

Field technicians lose connectivity on site. Notes taken offline must sync without data loss once the device is back online. This spec covers the client-side queue, the /sync endpoint and ADR 0007 on conflict handling.

Decision needed: last-writer-wins vs. CRDT merge for concurrent edits of the same note. See Conflict handling.

1. Goals

  • Never lose a note written offline.

  • Sync completes within 10 s of reconnecting for a typical day of notes.

  • Conflicts are visible to the user, never silently dropped.

    • Shown as a banner on the note.

    • Listed in the Conflicts inbox.

1.1 Non-goals

  1. Real-time collaboration between technicians.

  2. Syncing attachments larger than 25 MB.

    1. Those are uploaded separately via the media service.

  3. Web client support (mobile only for v1).

2. Flow

Online

Each save is pushed immediately. The outbox stays empty.

Offline

Saves are appended to the outbox and replayed in order on reconnect.

3. API

The client sends batches of operations. Each operation carries a client-generated id so retries are idempotent. 

interface SyncBatch {
  deviceId: string;
  ops: Array<{ id: string; noteId: string; kind: "upsert" | "delete"; at: number }>;
}

async function flush(outbox: Outbox): Promise<void> {
  const batch = await outbox.take(50);
  if (batch.ops.length === 0) return;
  await fetch("/sync", { method: "POST", body: JSON.stringify(batch) });
}

4. Conflict handling

“If two technicians edit the same note offline, neither should lose their text.”

— Field ops lead, interview 2026-10-12

We merge at paragraph granularity and mark overlapping edits.
