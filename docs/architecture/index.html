Building blocks

The repository has three building blocks: the source code in src/, the plugin folder plugin/ that the source is built into, and the end-to-end tests in e2e/.

src/ and its import rules

One folder per runtime environment: cli/ and server/ run in Node, web/ in the browser, shared/ in both. The rules are enforced by dependency-cruiser (.dependency-cruiser.cjs, mise run arch) before each commit that touches src/ and in CI (ADR 0002):

  • cli, server and web may import shared, but not each other. The CLI starts the built server as a process instead of importing its code.
  • shared imports none of the other folders and no Node built-ins; web imports no Node built-ins.
  • No circular imports, no orphan modules, no development-only dependency in shipped code.

TypeScript enforces the environments as well: tsconfig.node.json (Node types) covers src/cli, src/server, the end-to-end tests and the tool configs; tsconfig.web.json (DOM types) covers src/web; both include src/shared. Unit tests sit next to the code as ‹name›.test.ts.

Placeholder modules: shared/product.ts holds PRODUCT_NAME, the only place the working name appears in code; shared/greeting.ts builds the greeting; server/server.ts is a minimal node:http server (GET /api/hello, static files from the built page, 404 for missing files and paths that leave the web root, 405 for other methods); cli/cli.ts implements hello [name] and serve [--port n]; web/App.vue shows the greeting or “Server not reachable”.

plugin/

The plugin root: exactly what a user installs and what --plugin-dir loads. It contains no code of its own; the CLI, server and page come from src/ through the build. plugin/ has no package.json, so Claude Code never installs dependencies for it.

e2e/

e2e/fixtures.ts provides startCli(args), which runs plugin/bin/tandem, waits for the URL it prints and stops the process after the test. End-to-end tests therefore exercise the entry script and the bundles exactly as Claude Code runs them. e2e/hello.spec.ts is placeholder.

Cross-cutting concepts

Build and bundling

One vite.config.ts builds three outputs into plugin/dist/: the page (web/), the server (server.js) and the CLI (cli.js). The two Node outputs target Node 24 and inline every dependency, so only node: imports remain. Vite also defines a default ssr environment; the config's builder.buildApp builds only the three named environments (ADR 0003). plugin/bin/tandem is a bash 3.2 script that requires Node ≥ 24 and runs dist/cli.js (ADR 0004).

Tooling and checks

mise pins Node, pnpm and Claude Code and runs every task (mise.toml). Each checking tool has a local task that fixes what it can and a -ci variant that never changes files:

Coverage gate (test-ci): every source file changed since COVERAGE_BASE must reach 80 % line and branch coverage on its own. It uses Vitest's own coverage.changed: only the changed files are measured, each must pass the per-file threshold, and a changed file without tests counts as 0 %. The report in reports/coverage/ therefore covers only the changed files; mise run test -- --coverage measures and gates all files.

Known limit (Claude Code 2.1.319): during claude plugin eval runs, the plugin's bin/ is not on the Bash tool's PATH, so the agent test fails at tandem hello with operation not permitted: tandem. The same file runs inside the eval sandbox when called by its absolute path, and the bare command works in normal sessions with --plugin-dir. The test is kept as written until Claude Code fixes this; F10 should check again before relying on bare commands in agent tests.

CI

GitHub Actions on Linux. ci.yml: job check runs mise run check-ci as a matrix, once on the pinned Node 24 and once on the latest Node LTS (26, named explicitly), to notice early when a newer Node breaks something. pr-title.yml checks the pull-request title against Conventional Commits. agent-tests.yml runs the agent tests by hand or on the maintainer's agent-tests label. The required checks for main are check (pinned), check (26) and pr-title; merges are squash only (ADR 0006).

Deployment

The plugin reaches users through the marketplace at the repository root, whose single entry points at plugin/ on branch release (ADR 0005). Until F12 creates the release workflow, the plugin is only used in development.
