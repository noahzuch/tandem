F06 · Agent editing & merge engine specification pending

How Claude reads and edits the live document without disturbing the user.

Overview

While the document is open the agent edits only through the CLI: collab read (outline, section, current HTML with the user's caret marked) and collab patch (SEARCH/REPLACE on HTML), plus a few ops (move, single SVG labels). The server turns the new HTML into Yjs operations with a 3-way merge around updateYFragment, re-parsing only changed blocks. Includes caret awareness (probe, hints, proposals instead of refusals) and the merge-engine hardening from spikes 08 and 11.

What the spikes settled

  • collab patch by default; no Edit/Write on the open file — it caused refusals, change notices and a store race (08).
  • Four loss causes found and fixed in the merge; afterwards 0 lost on all paths with a browser user typing (08).
  • Word-level diff + caret records: 28/30 runs clean, the rest identical to two humans (11, N10).
  • Caret handling: always probe, apply + hint; turn rewrites of the words being typed into a proposal; refusal only as fallback (11, N19).
  • Risk #1: own the merge module, pin one y-tiptap version for server and browser, use verify suites as contract tests (risks).

Open / to decide

  • Which merge additions are workarounds for updateYFragment's pairing; own diff pairing blocks by id? (N4)
  • Keystroke in flight into a re-created block; caret records only cover plain text and grow unbounded (11).
  • set-block changing type while the user types; drop set-island-text once islands merge (open items, N20).
