Features / F05

F05 · Live collaboration specification pending

User and agent edit the same document at the same time without losing characters.

Overview

Yjs with a self-hosted Hocuspocus server binds every browser tab and the agent to one Y.Doc. Covers presence and remote carets (including the agent's caret), per-user undo, server-side initialisation so tabs never race, persistence across restarts and the workarounds for upstream bugs in the collaboration packages. Multiple human users work technically but are low priority.

What the spikes settled

  • No characters lost in every measured case except two bounded ones: both sides editing the same word, and both editing one diagram (07).
  • The browser never loads HTML itself; the server fills the Y.Doc, so two tabs can't race (07).
  • ⌘Z undoes only your own changes (07).
  • Upstream bugs: scrambled typing in @tiptap/y-tiptap 3.0.10 (06) and broken redo (07) — workarounds built; pin versions.

Open / to decide

  • Concurrent edits inside one diagram: one side lost; soft lock built, per-label storage not (07, N20).
  • Offline persistence in the browser (y-indexeddb) — not verified.
  • Multiple humans: works locally via ?user=, but no auth, identities or network binding low prio (N14).
