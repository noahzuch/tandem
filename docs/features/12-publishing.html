F12 · Publishing specification pending

Making the project release-ready: releases, distribution, upkeep and the public face.

Overview

Everything that turns a working repo into something others install and trust, and that can be added once the core works: release automation and versioning, publishing to a Claude plugin marketplace, automated dependency updates, README and docs, changelog, contribution and security policies. Builds on the tooling chosen in F00 · Project setup.

Starting points

  • nessy's release model is a known pattern: a manually triggered, CI-gated Release workflow that bumps the version, builds and advances a release branch users install from (not a spike result).
  • Collaboration packages must stay pinned and upgraded together, with the verify suites as contract tests (risks) — constrains dependency automation.
