Skill ↔ server ↔ browser ↔ agent: opening a document and getting browser events back to Claude.

Overview

The skill starts a local server per document, prints the URL and keeps a connection between the browser and the running Claude session. Browser actions (comments, “send to agent”, tab closed) are queued durably and delivered to the agent through a background collab wait whose exit wakes the agent. Covers the CLI lifecycle (open, wait, status, stop, peek for hooks), consumers and acking, port reuse, crash recovery and idle shutdown.

What the spikes settled

  • One detached server per document, state in .collab/<doc>/; open is safe to call any time and reuses a running server (01).
  • Background collab wait is the recommended wake-up; measured under 0.5 s from inside a subagent (01).
  • Durable event queue with per-consumer cursors, acked after printing → at-least-once delivery; a killed wait loses nothing (01).
  • CLI should be a plain binary in the plugin's bin/ — Claude Code's guard refused heredocs piped into npm run (08).

Open / to decide

  • Waking an idle main session with a background wait was never tried (open items).
  • Fate of watch, push and the 400 ms settle window (01 verdicts: remove / rethink / untested).
  • Plugin monitors and asyncRewake hooks — known from docs only.
